# 作业管理

作业管理是系统的核心模块，所有定时任务都在这里创建与维护。

![作业管理](/images/job.png)

## 1. 列表能力

- 分页、排序、按名称 / 分组 / 状态搜索；
- 显示作业状态：正常、暂停、完成、错误、阻塞；
- 启用 / 禁用开关，切换前二次确认；
- 操作菜单支持编辑、复制、立即执行、暂停 / 恢复、删除；
- 多选后执行批量操作；
- 搜索条件与列设置持久化。

## 2. 新增作业

点击「新增作业」，填写基本信息：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 作业名称 | 唯一标识 | `data-sync` |
| 作业分组 | 分类管理 | `DEFAULT` |
| 作业描述 | 简要说明 | `每日数据同步` |
| 作业类型 | 作业实现方式 | ClassJob / API |

### 2.1 作业类型

| 类型 | 说明 |
| --- | --- |
| ClassJob（DLL 模式） | 执行通过 `[QuartzJob]` 注册的 C# 类 |
| API 模式 | 调用配置的 HTTP 接口，无需编写作业代码 |

API 模式可配置：

- 请求地址与 HTTP 方法；
- 请求头 Key-Value 对；
- 请求体；
- 超时时间（1–99999 秒）。

![API 请求头编辑器](/images/job-api-headers.png)

## 3. 调度配置

### 3.1 Cron 表达式

最常用的调度方式，支持标准 Quartz Cron：

```text
0 0/5 * * * ?
```

系统内置 **Cron 表达式生成器**，可预览近 10 次执行时间，避免手写错误。

![Cron 生成器](/images/cron-helper.png)

### 3.2 简单调度

适合固定间隔任务：设置延迟、重复间隔与执行次数。

### 3.3 日历调度

基于日历规则，可排除特定日期，适合工作日场景。

## 4. 作业参数

可为作业配置 JSON 格式的作业数据，执行时通过扩展方法读取：

```csharp
var json = context.JobDetail.JobDataMap.GetJobDataJson();
var data = context.JobDetail.JobDataMap.GetJobData<SampleParam>();
```

## 5. 失败重试

v2.4.0 起支持失败重试配置组：

- 重试次数；
- 重试间隔时间；
- 无需在作业代码中手写重试逻辑。

## 6. 并发控制

v2.5.0 起支持「禁止并发执行」（`DisallowConcurrentExecution`）：

- 同一作业上一次未结束时，下一次触发不会并发执行；
- 配置保存后由 Quartz 的 `JobBuilder` 自动应用。

## 7. 作业依赖

在作业编辑对话框中配置「前置依赖」：

- 依赖作业最近一次必须成功，否则本次跳过；
- 保存时校验自依赖、不存在的依赖与循环依赖；
- 手动「立即执行」绕过依赖校验。

详见 [作业依赖](/guide/dependency)。

## 8. 批量操作

v2.6.0 起支持多选后批量：

- 批量暂停；
- 批量恢复；
- 批量启用；
- 批量禁用。

未选中作业时按钮自动禁用，执行前有二次确认，完成后返回成功 / 失败数量。批量启用会保留作业原来的暂停状态。

## 9. 其他操作

- **立即执行**：手动触发一次，忽略暂停状态与依赖校验；
- **复制作业**：以现有配置快速创建新作业；
- **删除作业**：同时清理关联日志（按版本行为）；
- **查看详情**：查看作业配置与最近执行情况。

## 10. 命名与分组建议

- 名称使用小写 + 短横线，如 `order-sync`；
- 按业务域分组：`ORDER`、`REPORT`、`SYSTEM`；
- 描述写清楚业务含义与负责人；
- 同一业务链路使用统一前缀，便于搜索与依赖配置。

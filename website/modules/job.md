# 作业管理

作业管理是系统的核心模块，作业的创建、调整、启停与调度器控制都在这里完成。

![作业管理](/images/job.png)

## 1. 列表与筛选

### 1.1 列表字段

| 字段 | 说明 |
| --- | --- |
| 作业名称 / 分组 | 唯一标识 |
| 作业类型 | DLL / API |
| 作业类名 / API | DLL 显示完整类名，API 显示请求地址 |
| Cron 表达式 | 当前调度规则 |
| 上次执行 / 下次执行 | 来自调度器实时值 |
| 状态 | 正常、已暂停、已完成、错误、阻塞 |
| 中断补跑 | ⚡ 开启、⊘ 关闭、— 跟随全局 |
| 前置依赖 | 已配置的依赖作业 |
| 是否启用 | Switch 开关 |
| 创建时间 | 支持排序 |

日常 Cron 作业通常只会在「正常」与「已暂停」之间切换，其余状态用于特定触发场景。

### 1.2 筛选与排序

- 按作业名称、分组、类名 / API 搜索；
- 按状态、是否启用筛选；
- 服务端分页，支持按名称、分组、执行时间、创建时间排序；
- 搜索条件、排序状态与列设置会持久化。

## 2. 新增与编辑

对话框分为四个分区，字段随作业类型变化。

### 2.1 基本信息

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| 作业名称 | 必填，≤100 字符 | 创建后不可修改 |
| 作业分组 | 必填，≤100 字符，默认 `DEFAULT` | 创建后不可修改 |
| 作业类型 | 必填 | DLL / API |

需要改名时，用「复制」创建副本，再删除旧作业。

### 2.2 调度设置

| 字段 | 说明 |
| --- | --- |
| Cron 表达式 | Quartz Cron，必填，≤200 字符 |
| 禁止并发执行 | 上一次未结束时，新触发等待而不是并发 |
| 前置依赖 | 依赖作业全部成功后才会执行 |
| 失败重试 | 重试次数 0–10，重试间隔 1–3600 秒 |
| 中断补跑 | 跟随全局 / 开启 / 关闭 |

Cron 输入框右侧提供「可视化生成」，可逐项配置并预览未来 10 次执行时间。

![Cron 生成器](/images/cron-helper.png)

### 2.3 作业配置（DLL）

| 字段 | 说明 |
| --- | --- |
| 作业类名 | 从已加载程序集的 `IJob` 类中选择，也可输入完整类名 |
| 作业数据 | JSON 参数，执行时通过扩展方法读取 |

```csharp
var json = context.JobDetail.JobDataMap.GetJobDataJson();
var data = context.JobDetail.JobDataMap.GetJobData<OrderSyncParam>();
```

作业数据支持失焦自动格式化与「JSON 格式化」按钮，格式非法会校验失败。

### 2.4 作业配置（API）

| 字段 | 说明 |
| --- | --- |
| API 地址 | 必填，绝对地址，仅支持 http / https |
| 请求方法 | GET / POST / PUT / DELETE / PATCH |
| 超时（秒） | 1–99999，默认 60 |
| 跳过 SSL 验证 | 建议只在开发 / 测试环境使用 |
| API 请求头 | Key-Value 编辑器，支持常用请求头下拉 |
| API 请求体 | JSON，GET 请求会提示通常不需要请求体 |

![API 请求头编辑器](/images/job-api-headers.png)

### 2.5 其他设置

| 字段 | 说明 |
| --- | --- |
| 描述 | ≤500 字符，建议写清业务含义与负责人 |
| 是否启用 | 关闭后不参与调度，配置与日志保留 |

## 3. 调度配置说明

### 3.1 Cron

采用六段（可带年份）Quartz Cron：

```text
秒 分 时 日 月 周 [年]
```

常用示例：

| 表达式 | 含义 |
| --- | --- |
| `0 0/5 * * * ?` | 每 5 分钟 |
| `0 0 2 * * ?` | 每天 02:00 |
| `0 30 9 ? * MON-FRI` | 工作日 09:30 |
| `0 0 1 1 * ?` | 每月 1 号 01:00 |

「日」与「周」通常一个使用 `?`，另一个指定值。

### 3.2 失败重试

由框架在作业失败后按间隔重试，无需在作业代码里写循环。

- 只适合幂等作业；
- 重试次数为 0 时不重试；
- 重试间隔在次数大于 0 时才可填写。

### 3.3 禁止并发执行

开启后使用 Quartz 的 `DisallowConcurrentExecution`：同一作业上一次执行未结束时，新的触发会等待上一次完成，而不是并发执行。适合执行时间可能超过调度间隔的作业。

### 3.4 中断补跑

| 选项 | 含义 |
| --- | --- |
| 跟随全局（默认） | 由系统配置的「默认允许中断补跑」决定 |
| 开启 | 该作业一律补跑 |
| 关闭 | 该作业一律不补跑，优先级最高 |

补偿是整段重跑（at-least-once），**非幂等作业请设为关闭**。详见 [中断恢复与排水调度](/guide/recovery)。

### 3.5 前置依赖

- 依赖作业最近一次执行必须成功，否则本次跳过；
- 跳过后写入「已跳过」日志并说明原因；
- 保存时校验自依赖、不存在的依赖与循环依赖；
- 手动「立即执行」绕过依赖校验。

详见 [作业依赖](/guide/dependency)。

## 4. 单个作业操作

操作列在鼠标悬停时展开：

| 操作 | 行为 |
| --- | --- |
| 编辑 | 修改 Cron、重试、并发、依赖与作业配置 |
| 复制 | 以现有配置创建副本，名称与分组加 `_Copy` |
| 立即执行 | 手动触发一次，忽略暂停状态与依赖校验 |
| 停止 / 恢复 | 暂停或恢复该作业的触发器 |
| 删除 | 删除作业与关联日志，执行中的实例会被中断 |

「立即执行」只表示触发请求已提交，结果需到日志页查看。

## 5. 批量操作

多选作业后可执行：

- 批量停止（暂停）；
- 批量恢复；
- 批量启用；
- 批量禁用；
- 批量删除。

未选中作业时按钮禁用，执行前二次确认，完成后返回成功与失败数量。**批量启用会保留作业原来的暂停状态**。

## 6. 调度器与排水

页面顶部状态条展示当前调度器实例，并提供调度器级操作：

| 操作 | 行为 |
| --- | --- |
| 启动调度器 | 启动并重新加载启用且未暂停的作业 |
| 停止调度器 | 立即关闭，执行中的实例被中断并标记 |
| 排水 | 停止接收新触发，等待执行中任务收尾后自动停止 |
| 恢复调度 | 排水未完成时退出排水，继续接收触发 |

排水期间：

- 顶部显示「排水 · 等待 N 个任务完成」；
- 启动按钮置灰，手动触发会被拒绝；
- 执行中任务归零后自动关闭调度器；
- 超时未完成的任务被标记为「中断」，下次启动按补偿策略处理。

详见 [中断恢复与排水调度](/guide/recovery)。

## 7. 页面边界

为避免误解，以下能力**不在作业页提供**：

- 作业独立详情页（配置在编辑对话框，结果在日志页）；
- 单个作业的统计图表（统计在分析页）；
- 按作业配置通知渠道（通知为系统级配置）；
- 简单调度 / 日历调度（仅支持 Cron）。

## 8. 命名与分组建议

- 名称使用小写 + 短横线：`order-sync`、`report-daily`；
- 按业务域分组：`ORDER`、`REPORT`、`SYSTEM`；
- 描述写清输入、输出与负责人；
- 同一链路使用统一前缀，便于搜索与配置依赖。

# 日志管理

日志管理记录所有作业的执行过程与结果，是排查失败与优化性能的主要入口。

![日志管理](/images/log.png)

## 1. 日志内容

每条日志包含：

- 作业名称与分组；
- 开始时间、结束时间、执行耗时；
- 执行状态：运行中、成功、失败、已跳过；
- 执行消息；
- 错误信息（失败时）；
- 作业数据快照。

## 2. 查询与筛选

- 按作业名称 / 分组搜索；
- 按状态筛选（运行中、成功、失败、已跳过）；
- 按时间范围筛选（ISO 8601）；
- 支持服务端分页与排序；
- 搜索条件与列设置持久化。

## 3. 日志详情

点击「查看详情」打开详情对话框：

- 顶部状态色条标识执行结果；
- 元数据区展示作业、分组、耗时、时间；
- 错误信息与作业数据支持 JSON 格式化与复制；
- 执行时长列宽已优化，便于阅读。

![日志详情](/images/log-detail.png)

## 4. 「已跳过」状态

作业依赖不满足时，会写入「已跳过」日志并说明原因：

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 最近一次执行状态为 Failed
```

列表支持按该状态筛选，便于定位被依赖卡住的作业。详见 [作业依赖](/guide/dependency)。

## 5. 日志自动清理

v2.6.0 起在「系统配置」页提供自动清理：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 日志保留天数 | 30 | 超过天数自动清理，0 = 不按天数清理 |
| 日志最大条数 | 0 | 超过条数清理最旧日志，0 = 不限制 |
| 清理间隔（小时） | 6 | 后台清理任务的执行周期 |

后台服务启动 60 秒后开始工作，按配置循环执行，同时支持按天数和按条数两种策略。

```text
[作业日志自动清理] 清理完成，共清理 153 条日志，下次清理间隔 6 小时
```

详见 [系统配置](/modules/system-config)。

## 6. 排查建议

1. 先按状态筛选失败与已跳过，快速定位异常；
2. 打开详情查看错误信息与作业数据；
3. 对照执行耗时，判断是否超时或资源不足；
4. 若失败集中在同一时段，检查调度密度与依赖；
5. 修复后可通过「立即执行」验证。

# 日志管理

日志管理记录所有作业的执行过程与结果，是排查失败与优化性能的主要入口。

![日志管理](/images/log.png)

## 1. 日志内容

每条日志包含：

- 作业名称与分组；
- 开始时间、结束时间、执行耗时；
- 执行状态：运行中、成功、失败、已跳过、中断；
- 触发来源：定时 / 手动 / 补偿重跑；
- 执行消息；
- 错误信息（失败时）；
- 作业数据快照；
- 恢复信息（中断与补偿记录）：最后心跳、失联时长、补偿状态、跳过原因。

## 2. 查询与筛选

- 按作业名称 / 分组搜索；
- 按状态筛选（运行中、成功、失败、已跳过、中断）；
- 「仅看异常」开关：只显示失败与中断，开启后忽略状态筛选；
- 按时间范围筛选（ISO 8601）；
- 支持服务端分页与排序；
- 搜索条件与列设置持久化。

## 3. 日志详情

点击「查看详情」打开详情对话框：

- 顶部状态色条标识执行结果；
- 元数据区展示作业、分组、耗时、时间与触发来源；
- 错误信息与作业数据支持 JSON 格式化与复制；
- 执行时长列宽已优化，便于阅读。

![日志详情](/images/log-detail.png)

## 4. 「已跳过」状态

作业依赖不满足时，会写入「已跳过」日志并说明原因：

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 最近一次执行状态为 Failed
```

列表支持按该状态筛选，便于定位被依赖卡住的作业。详见 [作业依赖](/guide/dependency)。

## 5. 「中断」状态与重新执行

进程崩溃、强杀或停机超时后，未收尾的执行会被判定为「中断」（洋红标识）。中断记录：

- 展示最后心跳时间、失联时长与补偿状态；
- 若被自动补偿过，「触发来源」显示为「补偿重跑」，可回看原执行时间与第几次执行；
- 操作列提供「重新执行」，仅中断行可见，提交前提示会整段重跑。

补偿规则、开关与语义边界见 [中断恢复与排水调度](/guide/recovery)。

## 6. 日志配置

v2.7.0 起日志清理配置搬到日志页（原在系统配置页），点击「日志配置」直接修改：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用自动清理 | 开启 | 关闭后只能手动清理 |
| 保留天数 | 30 | 超过天数自动清理，0 = 不按天数清理 |
| 最大保留条数 | 0 | 超过条数清理最旧日志，0 = 不限制 |
| 清理间隔（小时） | 6 | 后台清理任务的执行周期（1–168） |

后台服务启动 60 秒后开始工作，按配置循环执行，同时支持按天数和按条数两种策略。

```text
[作业日志自动清理] 清理完成，共清理 153 条日志，下次清理间隔 6 小时
```

待补偿的中断记录不会被自动清理，避免丢失恢复依据。详见 [系统配置](/modules/system-config)。

## 7. 排查建议

1. 先开启「仅看异常」，快速筛出失败与中断记录；
2. 打开详情查看错误信息与作业数据；中断记录先看最后心跳与补偿状态；
3. 对照执行耗时，判断是否超时或资源不足；
4. 若失败集中在同一时段，检查调度密度与依赖；
5. 修复后可通过「立即执行」或中断记录的「重新执行」验证。

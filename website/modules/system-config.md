# 系统配置

系统配置页用于多实例区分、日志治理与存储迁移。

## 1. 服务标识

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| 服务名称 | 当前调度服务的名称 | `order-center-job` |
| 环境标识 | DEV / TEST / UAT / PROD | `PROD` |
| 服务描述 | 补充说明 | `订单中心定时任务` |

配置完成后，分析页顶部会展示服务标识，多实例部署时可以快速区分环境。

## 2. 日志自动清理

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 日志保留天数 | 30 | 超过天数自动清理，0 = 不按天数清理 |
| 日志最大条数 | 0 | 超过条数清理最旧日志，0 = 不限制 |
| 清理间隔（小时） | 6 | 后台清理任务的执行周期 |

机制：

- 后台服务启动 60 秒后开始工作；
- 之后按配置的间隔循环清理；
- 同时支持按保留天数与最大条数两种策略；
- 清理完成后输出日志，例如：

```text
[作业日志自动清理] 清理完成，共清理 153 条日志，下次清理间隔 6 小时
```

清理不占用前台请求，配置一次长期生效。

## 3. 数据迁移

系统配置页提供可视化数据迁移入口：

- 卡片标题展示当前存储类型；
- 选择源与目标存储（仅一种可用存储时会给出配置提示）；
- 预检数据量（弹窗展示）；
- 选择写入模式与迁移内容；
- 通过「查看摘要」弹窗查看分阶段进度与结果；
- 获取迁移后的配置建议。

![数据迁移](/images/migration-ui.png)

完整说明见 [数据迁移](/guide/migration)。

## 4. 配置存储

系统配置保存在存储层中（文件存储为 `settings.json`，数据库存储为 `quartz_settings` 表），会随数据迁移一起复制。

::: tip 与 appsettings.json 的区别
`appsettings.json` 中的 `QuartzUI` 节负责启动参数（存储、JWT、账号密码等）；系统配置页负责运行期业务配置（服务标识、日志清理等）。两者互不覆盖。
:::

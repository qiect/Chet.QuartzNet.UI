# 系统配置

系统配置页用于多实例区分、停机与恢复策略配置、存储迁移，页面顶部提供「停机与恢复 / 数据迁移」分区切换。

## 1. 服务标识

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| 服务名称 | 当前调度服务的名称 | `order-center-job` |
| 环境标识 | DEV / TEST / UAT / PROD | `PROD` |
| 服务描述 | 补充说明 | `订单中心定时任务` |

配置完成后，分析页顶部与浏览器标题会展示服务标识，多实例部署时可以快速区分环境。

## 2. 停机与恢复

v2.7.0 新增的启动期配置，保存后**需重启应用**生效；与当前进程实际生效值存在差异时会提示「重启后生效 N 项」，点开可对比旧值与新值。

v2.7.1 起，分区标题右侧提供「恢复默认」，可一键把停机与恢复相关配置还原为出厂值；该操作只修改表单，仍需保存后才会落库并生效。

### 2.1 停机策略

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 停机模式 | 排水后停止 | 立即停止 / 排水后停止 |
| 排水超时（秒） | 60 | 排水模式下最多等待的时间，超时后把未完成执行标记为中断 |
| 等待完成超时（秒） | 30 | 兼容旧配置保留，实际统一使用排水超时 |

> 应用关闭时的等待受宿主 `HostOptions.ShutdownTimeout`（默认 30 秒）约束，希望等待更久需同步调大。

### 2.2 中断恢复

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用中断补偿 | 开启 | 关闭后只标记中断，不补跑 |
| 补偿延迟（秒） | 30 | 启动后延迟多久开始补偿 |
| 心跳间隔（秒） | 15 | 运行中任务写心跳的周期 |
| 租约时长（秒） | 60 | 超过该时长未续期即判定中断，必须 ≥ 2 × 心跳间隔 |
| 临近触发跳过阈值（秒） | 120 | 距下次触发不足该秒数时跳过补偿 |
| 补偿策略 | 每个作业补最近一次 | 只标记不补偿 / 补最近一次 / 全部补偿 |
| 最大执行次数 | 3 | 同一执行链最大补偿次数 |
| 默认允许中断补跑 | 开启 | 作业未显式配置时的默认值 |
| 中断日志保留（天） | 30 | 中断与补偿链日志的保留策略 |

保存时服务端强制校验取值范围与「租约 ≥ 2 × 心跳」，不满足直接拒绝，不做静默纠正；选择「全部补偿」会二次确认。

完整语义与操作步骤见 [中断恢复与排水调度](/guide/recovery)。

## 3. 日志清理（已迁移）

日志自动清理配置已迁移到 [日志管理](/modules/log) 页的「日志配置」，系统配置页不再提供该分组，历史配置值与清理行为保持不变。

## 4. 数据迁移

系统配置页提供可视化数据迁移入口：

- 卡片标题展示当前存储类型；
- 选择源与目标存储（仅一种可用存储时会给出配置提示与空状态引导）；
- 预检数据量（弹窗展示）；
- 选择写入模式与迁移内容；
- 通过「查看摘要」弹窗查看分阶段进度与结果；
- 获取迁移后的配置建议。

![数据迁移](/images/migration-ui.png)

完整说明见 [数据迁移](/guide/migration)。

## 5. 配置存储

系统配置保存在存储层中（文件存储为 `settings.json`，数据库存储为 `quartz_settings` 表），会随数据迁移一起复制。

::: tip 与 appsettings.json 的区别
`appsettings.json` 中的 `QuartzUI` 节负责启动参数（存储、JWT、账号密码等）；系统配置页负责运行期业务配置（服务标识、停机与恢复策略等）。两者互不覆盖。
:::

# 系统配置

系统配置页用于三件事：区分多实例、配置停机与恢复策略、迁移存储数据。页面顶部提供「停机与恢复 / 数据迁移」分区切换。

## 1. 服务标识

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| 服务名称 | 当前调度服务的名称，同时用于浏览器标题 | `order-center-job` |
| 环境标识 | DEV / TEST / UAT / PROD | `PROD` |
| 服务描述 | 补充说明，分析页顶部展示 | `订单中心定时任务` |

配置保存在存储层，会随数据迁移一起复制。多实例部署时应为每个实例设置可区分的名称与环境。

## 2. 停机与恢复

v2.7.0 新增的启动期配置。保存后**需重启应用**才生效；与当前进程实际生效值有差异时，页面提示「重启后生效 N 项」，可展开对比旧值与新值。

v2.7.1 起，分区标题右侧提供「恢复默认」。该按钮只还原表单，仍需保存后落库。

### 2.1 停机

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 停机模式 | 排水后停止 | 立即停止 / 排水后停止 |
| 排水超时（秒） | 60 | 排水模式下最多等待时间，超时后未完成执行被标记为中断 |

「等待完成超时」是旧版本字段，已并入「排水后停止」，不再在界面单独配置。

> 应用关闭时的等待还受宿主 `HostOptions.ShutdownTimeout`（默认 30 秒）约束，希望等待更久时需同步调大。

### 2.2 中断恢复

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用中断补偿 | 开启 | 关闭后只标记中断，不补跑 |
| 补偿延迟（秒） | 30 | 启动后延迟多久开始补偿 |
| 心跳间隔（秒） | 15 | 执行中任务写心跳的周期 |
| 租约时长（秒） | 60 | 超过该时长未续期即判定中断，必须 ≥ 2 × 心跳间隔 |
| 临近触发跳过阈值（秒） | 120 | 距下次触发不足该秒数时跳过补偿 |
| 补偿策略 | 每个作业补最近一次 | 只标记不补偿 / 补最近一次 / 全部补偿 |
| 最大执行次数 | 3 | 同一执行链最多执行到第几次，含原执行 |
| 默认允许中断补跑 | 开启 | 作业未单独配置时的默认值 |
| 中断日志保留（天） | 30 | 中断与补偿链日志保留；0 跟随普通日志策略 |

保存时服务端校验：

- 取值范围；
- 「租约 ≥ 2 × 心跳」；
- 选择「全部补偿」时二次确认。

完整语义见 [中断恢复与排水调度](/guide/recovery)。

## 3. 数据迁移

系统配置页提供可视化迁移入口，支持文件与 MySQL / PostgreSQL / SQLite / SQL Server 之间互转。

### 3.1 操作流程

1. 卡片展示当前存储类型；
2. 选择源存储与目标存储（仅一种可用存储时给出空状态提示）；
3. 预检数据量，查看预计插入 / 更新 / 跳过数量；
4. 选择写入模式与迁移内容（作业、日志、系统设置、通知）；
5. 执行迁移，通过「查看摘要」查看进度与结果；
6. 查看迁移后的配置建议。

![数据迁移](/images/migration-ui.png)

### 3.2 三种写入模式

| 模式 | 语义 |
| --- | --- |
| 合并 Merge | 不存在则插入，存在则跳过 |
| 覆盖 Overwrite | 不存在则插入，存在则更新 |
| 替换 Replace | 先清空目标所选实体，再全量写入 |

`Replace` 默认不可用，需要在配置中开启 `QuartzUI:Migration:AllowReplace`，执行前仍会二次确认。

### 3.3 注意事项

- 迁移不会自动修改存储配置，完成后需手动改 `StorageType`、`DatabaseProvider` 与连接字符串并重启；
- 文件源会自动备份，**数据库源不会**，迁移前请自行备份；
- 目标数据库会自动建表并应用迁移；
- 迁移后做数量校验与抽样比对，差异只告警不阻断；
- 连接字符串只保存在服务端，不会下发到浏览器。

完整说明见 [数据迁移](/guide/migration)。

## 4. 配置存储

| 存储 | 位置 |
| --- | --- |
| 文件 | `setting.json` |
| 数据库 | `quartz_settings` 表 |

::: tip 与 appsettings.json 的区别
`appsettings.json` 的 `QuartzUI` 节负责启动参数（存储、JWT、账号密码等）；系统配置页负责运行期业务配置（服务标识、停机与恢复策略等）。两者互不覆盖。
:::

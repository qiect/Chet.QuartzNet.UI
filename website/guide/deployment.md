# 部署与升级

## 1. 部署模型

Chet.QuartzNet.UI 以 RCL 形式嵌入宿主应用，**不需要单独部署前端或独立服务**。发布宿主应用即可同时带上管理界面与 API。

```bash
dotnet publish -c Release -o publish
```

启动后访问：

```text
https://your-domain/quartz-ui
```

## 2. 生产环境配置建议

| 项目 | 建议 |
| --- | --- |
| `JwtSecret` | 使用随机生成的强密钥，不要使用文档示例值 |
| `UserName` / `Password` | 修改默认账号密码 |
| `JwtExpiresInMinutes` | 按安全要求设置，避免过长 |
| `StorageType` | 生产环境优先使用数据库存储 |
| `FileStoragePath` | 文件模式下挂载持久化卷，避免容器重建丢数据 |
| 反向代理 | 确保 `/quartz-ui` 与 API 路由可正常转发 |

::: tip 多实例部署
文件存储不适合多副本共享写入。多实例场景请使用数据库存储，并确保所有实例连接同一个数据库。
:::

## 3. 数据库部署

1. 创建空数据库并授权；
2. 安装对应 EFCore 扩展包；
3. 配置连接字符串与 `DatabaseProvider`；
4. 首次启动自动建表；
5. 升级版本后如有结构变更，执行：

```bash
dotnet ef database update
```

建议在生产升级前：

- 备份数据库；
- 在测试环境先执行一次升级；
- 确认主包与 EFCore 扩展包版本一致。

## 4. Docker 部署要点

- 文件存储模式：将 `App_Data/QuartzJobs` 挂载为卷；
- 数据库存储模式：通过环境变量或配置文件注入连接字符串；
- 容器内时区需与应用预期一致，避免 Cron 触发时间偏差；
- 单副本使用文件存储，多副本使用数据库存储。

## 5. 版本升级清单

以 v2.6.0 为例：

```bash
# 1. 更新主包
dotnet add package Chet.QuartzNet.UI --version 2.6.0

# 2. 同步更新数据库扩展包
dotnet add package Chet.QuartzNet.EFCore.MySQL --version 2.6.0

# 3. 数据库结构升级
dotnet ef database update
```

升级前检查：

- [ ] 已备份数据（文件目录或数据库）
- [ ] 主包与扩展包版本一致
- [ ] 数据库迁移脚本已在测试环境验证
- [ ] 通知、JWT 等配置未被覆盖
- [ ] 升级后登录、作业列表、日志、通知均正常

### 文件存储升级

文件存储无需额外操作，程序启动后自动兼容旧数据文件，新增字段默认为空。

### 数据库存储升级

如果只升级主包而不升级 EFCore 扩展包，新增字段可能写入失败。例如 v2.6.0 新增作业依赖字段，需要四个数据库提供程序同步更新并执行 `AddJobDependencies` 迁移。

## 6. 回滚建议

- 升级前保留旧版本包与数据库备份；
- 回滚时同时回退主包与扩展包版本；
- 若数据库已执行新迁移，回滚前先确认旧版本是否兼容新结构；
- 文件存储可直接恢复备份目录。

## 7. 发布检查

- [ ] 使用 HTTPS 暴露管理界面；
- [ ] 修改默认账号密码与 JWT 密钥；
- [ ] 限制管理界面的访问来源（网关 / IP 白名单）；
- [ ] 配置日志与通知，确认失败可被感知；
- [ ] 配置日志自动清理，避免数据无限增长；
- [ ] 验证备份与恢复流程。

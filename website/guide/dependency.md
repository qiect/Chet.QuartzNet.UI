# 作业依赖

## 1. 轻量版工作流

「A 跑完再跑 B」是定时任务最常见的诉求。Chet.QuartzNet.UI 没有做复杂的 DAG 编辑器，而是采用直观的**前置校验模式**：

1. 作业被触发时，先检查所有前置依赖作业；
2. 逐个查看依赖作业**最近一次执行**的结果；
3. 全部成功 → 正常执行本作业；
4. 有任意一个未执行或执行失败 → **本次直接跳过**，不执行作业本体；
5. 等待下一次触发再判断。

依赖关系以 JSON 存储在作业数据中，文件存储与数据库存储都支持，数据迁移时也会一并复制。

## 2. 配置方式

在作业编辑对话框中找到「前置依赖」多选框：

- 按 `分组 / 作业名` 选择依赖作业；
- 支持多选与搜索；
- 支持一键清空。

## 3. 执行规则

| 依赖状态 | 本次结果 |
| --- | --- |
| 全部依赖最近一次成功 | 正常执行 |
| 任一依赖最近一次失败 | 跳过 |
| 任一依赖尚未执行 | 跳过 |
| 没有配置依赖 | 正常执行 |

依赖不满足时不会静默跳过，而是写入一条「已跳过」状态日志，说明具体原因：

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 最近一次执行状态为 Failed
```

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 尚未执行
```

日志管理页支持按「已跳过」筛选，方便定位被依赖卡住的作业。

## 4. 保存时的三重校验

| 校验项 | 提示 |
| --- | --- |
| 依赖自己 | 作业不能依赖自身 |
| 依赖不存在的作业 | 依赖作业不存在: 分组.名称 |
| 形成循环依赖（A → B → A） | 存在循环依赖，请检查前置依赖配置 |

校验在保存时完成，避免把错误配置写入存储。

## 5. 手动触发不走依赖校验

「立即执行」是人工干预手段，与「手动触发忽略暂停状态」保持一致：**手动触发会绕过依赖校验**，方便在依赖异常时手动补跑。

## 6. 使用建议

- 依赖只做「前置校验」，不会自动触发下游作业；
- 下游作业仍需配置自己的 Cron 触发时间；
- 尽量让依赖链保持短小，避免多层依赖导致排查困难；
- 对关键链路配合失败通知，及时发现上游异常；
- 跨实例部署时，依赖状态基于共享存储，请确保多实例使用同一数据库。

# 常见问题

## 集成与访问

### Q：管理界面的默认访问地址是什么？

`/quartz-ui`，例如 `http://localhost:5000/quartz-ui`。

### Q：需要单独部署前端吗？

不需要。前端静态资源随 NuGet 包发布，`UseQuartz()` 会挂载路由与资源。

### Q：支持哪些 .NET 版本？

.NET 8.0 与 .NET 10.0，对应 ASP.NET Core 8.0+ / 10.0+。

### Q：可以集成到已有的 ASP.NET Core 项目吗？

可以。添加包、调用 `AddQuartzUI()` 与 `UseQuartz()` 即可，不会改变现有项目结构。

## 存储

### Q：如何切换存储模式？

修改 `QuartzUI:StorageType`、`DatabaseProvider` 与连接字符串后重启。已有数据请使用「数据迁移」功能搬运，详见 [数据迁移](/guide/migration)。

### Q：支持哪些数据库？

MySQL、PostgreSQL、SQL Server、SQLite，分别安装对应的 EFCore 扩展包。

### Q：数据库表会自动创建吗？

会。启动时由 EF Core 迁移自动建表；升级版本后如包含结构变更，执行 `dotnet ef database update`。

### Q：数据库存储和文件存储可以同时使用吗？

运行时只能选择一种存储。迁移功能可以在两者之间搬运数据，但不会同时写入两份。

### Q：文件数据存放在哪里？

默认 `App_Data/QuartzJobs/`，可通过 `FileStoragePath` 修改。

## 作业

### Q：ClassJob 没有出现在列表里？

检查：

1. 是否调用了 `AddQuartzClassJobs()`；
2. 作业类是否为 `public` 且实现 `IJob`；
3. 是否标记了 `[QuartzJob]`；
4. 名称与分组是否与已有作业冲突。

### Q：作业执行失败会自动重试吗？

v2.4.0 起支持失败重试配置组，可设置重试次数与重试间隔。未配置时不重试。

### Q：可以禁止同一个作业并发执行吗？

可以。v2.5.0 起支持「禁止并发执行」，对应 `DisallowConcurrentExecution`。

### Q：作业依赖不满足会怎样？

本次跳过，不执行作业本体，并写入一条「已跳过」日志，下一次触发重新判断。手动「立即执行」会绕过依赖校验。

### Q：如何批量暂停或启用作业？

在作业列表多选后使用工具栏的「批量操作」，支持批量暂停、恢复、启用、禁用。

## 日志与通知

### Q：日志会无限增长吗？

不会。系统配置页可设置日志保留天数、最大条数与清理间隔，后台定时清理。默认保留 30 天。

### Q：通知发送失败怎么排查？

检查 PushPlus Token、网络连通性、推送渠道与模板是否匹配，并查看通知历史中的错误信息。

### Q：为什么作业成功时没有收到通知？

「作业成功时发送」默认关闭，需要在通知策略中手动开启。

## 升级与运维

### Q：升级后数据库报字段缺失？

主包与 EFCore 扩展包版本不一致。请同步升级扩展包并执行 `dotnet ef database update`。

### Q：多实例部署应该用哪种存储？

数据库存储。文件存储适合单实例，多副本共享目录可能产生写入冲突。

### Q：升级会丢失数据吗？

不会。文件存储自动兼容旧数据；数据库存储通过 EF Core 迁移升级结构。仍建议升级前备份。

### Q：如何修改登录账号密码？

修改 `appsettings.json` 中的 `QuartzUI:UserName` 与 `Password`，重启应用生效。

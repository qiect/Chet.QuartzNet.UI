# v2.6.0：作业依赖、批量操作与存储迁移

v2.6.0 发布于 2026-11-03。这一版没有加新的“大模块”，而是围绕日常运维最常遇到的四件事：**任务先后顺序、批量处理、日志增长、存储更换**。

## 1. 作业依赖

### 1.1 执行规则

给作业配置一个或多个前置依赖后，每次触发按以下逻辑判断：

1. 逐个检查依赖作业**最近一次执行**结果；
2. 全部成功 → 执行本作业；
3. 任意一个未执行、失败或已跳过 → 本次直接跳过，不执行作业本体。

它没有做 DAG 编排或自动触发链路，只做前置校验，逻辑简单、可预期。

### 1.2 配置方式

作业编辑对话框 →「调度设置」→「前置依赖」，按「分组 / 作业名」多选，支持搜索与一键清空。

依赖关系以 JSON 存入作业表（文件存储写入 `jobs.json`），数据迁移时会一并复制。

### 1.3 跳过会留下日志

依赖不满足时写入一条「已跳过」记录，消息中说明原因：

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 最近一次执行状态为 Failed
```

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 尚未执行
```

日志页支持按「已跳过」筛选。

### 1.4 保存时校验

| 校验 | 提示 |
| ---- | ---- |
| 依赖自己 | 作业不能依赖自身 |
| 依赖不存在 | 依赖作业不存在: 分组.名称 |
| 循环依赖 | 存在循环依赖，请检查前置依赖配置 |

### 1.5 手动触发不校验依赖

「立即执行」是人工干预手段，会绕过依赖校验，也忽略暂停状态，方便在依赖异常时补跑。

## 2. 批量操作

作业列表支持多选后：

- 批量暂停（停止）；
- 批量恢复；
- 批量启用；
- 批量禁用。

行为说明：

- 未选中作业时按钮禁用；
- 执行前二次确认；
- 完成后返回成功与失败数量；
- 批量启用**保留作业原来的暂停状态**，不会因为一次启用就自动运行。

批量删除在更早版本（1.6.0）已支持，同样会清理关联日志。

## 3. 日志自动清理

日志持续增长会拖慢查询。v2.6.0 增加了后台清理服务：

| 配置项 | 默认值 | 说明 |
| ------ | ------ | ---- |
| 保留天数 | 30 | 超过天数清理，0 = 不按天数 |
| 最大保留条数 | 0 | 超过条数清理最旧日志，0 = 不限 |
| 清理间隔 | 6 小时 | 后台任务周期 |

应用启动 60 秒后开始工作，之后按间隔循环。清理结果输出到日志：

```text
[作业日志自动清理] 清理完成，共清理 153 条日志，下次清理间隔 6 小时
```

> v2.6.0 时这组配置位于系统设置页；v2.7.0 起迁移到日志页的「日志配置」，并新增「启用自动清理」开关。

## 4. 存储数据迁移

### 4.1 支持的存储

| 存储 | 标识 | 依赖包 |
| ---- | ---- | ------ |
| 文件 | `File` | 无 |
| MySQL | `MySql` | `Chet.QuartzNet.EFCore.MySQL` |
| PostgreSQL | `PostgreSql` | `Chet.QuartzNet.EFCore.PostgreSQL` |
| SQLite | `SQLite` | `Chet.QuartzNet.EFCore.SQLite` |
| SQL Server | `SqlServer` | `Chet.QuartzNet.EFCore.SqlServer` |

五种存储任意两两互转，共 20 个方向。同一存储类型之间不允许直接迁移，需要先导出到文件再导入。

### 4.2 迁移内容

| 数据 | 业务键 | 说明 |
| ---- | ------ | ---- |
| 作业数据 | `JobGroup` + `JobName` | 定义、触发器、Cron、状态、依赖 |
| 作业日志 | `LogId` | 执行历史 |
| 系统设置 | `Key` | 键值配置 |
| 通知消息 | `NotificationId` | 通知历史 |

默认四类全选。服务端按「系统设置 → 作业数据 → 通知消息 → 作业日志」的顺序写入，避免作业先于设置落库。

### 4.3 三种写入模式

| 模式 | 语义 | 适用场景 |
| ---- | ---- | -------- |
| 合并 Merge | 不存在则插入，存在则跳过 | 增量同步，可重复执行 |
| 覆盖 Overwrite | 不存在则插入，存在则更新 | 以源为准刷新目标 |
| 替换 Replace | 先清空目标所选实体，再全量写入 | 整体搬迁、环境重建 |

`Replace` 默认不可用，需要在配置中显式开启：

```json
{
  "QuartzUI": {
    "Migration": {
      "AllowReplace": true
    }
  }
}
```

开启后执行前仍会二次确认，因为该操作会删除目标端数据。

### 4.4 预检、进度与校验

1. **预检**：统计源端与目标端数量、预计插入 / 更新 / 跳过；
2. **后台执行**：页面轮询进度；
3. **自动建表**：数据库目标自动执行 EF Core 迁移；
4. **分批处理**：默认每批 500 条（可配 1–2000），文件端日志与通知采用流式读写；
5. **迁移后校验**：数量校验 + 首 / 中 / 尾抽样，差异只告警不阻断；
6. **可选暂停调度器**：迁移期间把调度器置为 Standby，避免写入被任务执行干扰。

### 4.5 备份与安全

- 文件源会自动备份；**数据库源不会自动备份**，请提前自行备份；
- 连接字符串只保存在服务端，不会下发到浏览器；
- 文件路径必须在 `FileStoragePath` 或 `FileSources` 白名单内；
- 迁移不会自动修改存储配置，完成后需手动修改 `StorageType`、`DatabaseProvider` 与连接字符串并重启。

### 4.6 配置附加存储

当前存储与另一个数据库之间迁移时，配置 `AdditionalStore`：

```json
{
  "QuartzUI": {
    "Migration": {
      "AdditionalStore": {
        "Provider": "MySQL",
        "ConnectionString": "Server=127.0.0.1;Port=3306;Database=quartzui;User=root;Password=***;"
      }
    }
  }
}
```

旧版的 `Migration.Profiles` 仍然兼容，但推荐使用 `AdditionalStore`。

## 5. 升级指南

### 5.1 更新包

```bash
dotnet add package Chet.QuartzNet.UI --version 2.6.0
```

数据库存储模式同步更新：

```bash
dotnet add package Chet.QuartzNet.EFCore.MySQL --version 2.6.0
dotnet add package Chet.QuartzNet.EFCore.PostgreSQL --version 2.6.0
dotnet add package Chet.QuartzNet.EFCore.SqlServer --version 2.6.0
dotnet add package Chet.QuartzNet.EFCore.SQLite --version 2.6.0
```

### 5.2 数据库结构

v2.6.0 新增作业依赖字段，四个提供程序均包含对应迁移。启动时自动执行 `MigrateAsync()`，无需手动命令。

::: warning
只升级主包、不升级 EFCore 扩展包时，依赖字段会写入失败。两者版本必须一致。
:::

### 5.3 文件存储

无需操作，旧 JSON 缺少依赖字段时默认为空。

## 6. 本次更新一览

| 能力 | 类型 | 说明 |
| ---- | ---- | ---- |
| 作业依赖 | 新增 | 依赖未满足则跳过并记录日志 |
| 批量操作 | 新增 | 批量暂停 / 恢复 / 启用 / 禁用 |
| 日志自动清理 | 新增 | 按天数与条数后台清理 |
| 已跳过状态 | 新增 | 日志展示与筛选 |
| 存储数据迁移 | 新增 | 五种存储互转，预检 + 校验 + 三种模式 |
| 迁移依赖同步 | 优化 | 迁移时复制作业依赖字段 |

## 7. 小结

v2.6.0 的取舍很明确：不做 RBAC、审批流、DAG 编排，只把高频运维场景做顺。需要复杂工作流时，应在业务层或专业调度平台解决。

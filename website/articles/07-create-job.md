# 新增作业指南：字段逐个说明

「新增作业」是使用频率最高的入口。它的表单项不少，但可以按四个分区理解：**基本信息、调度设置、作业配置、其他设置**。下面按界面顺序逐个说明。

## 1. 先选作业类型

| 类型 | 执行内容 | 什么时候选 |
| ---- | -------- | ---------- |
| DLL | 调用应用内实现了 `IJob` 的类 | 业务逻辑在代码里，需要依赖注入、事务或本地服务 |
| API | 发送一次 HTTP 请求 | 只需触发其他服务的接口 |

作业类型决定「作业配置」区显示哪些字段，两者不能混用。

## 2. 基本信息

| 字段 | 约束 | 说明 |
| ---- | ---- | ---- |
| 作业名称 | 必填，≤100 字符 | 与分组共同唯一标识一个作业 |
| 作业分组 | 必填，≤100 字符，默认 `DEFAULT` | 用于分类与筛选 |
| 作业类型 | 必填 | DLL / API |

::: warning
作业名称与分组在创建后不可修改，编辑时输入框是禁用的。需要改名时，用「复制」生成新作业，再删除旧作业。
:::

## 3. 调度设置

### 3.1 Cron 表达式

使用 Quartz Cron，格式为六段（或带年份的七段）：

```text
秒 分 时 日 月 周 [年]
```

常用示例：

| 表达式 | 含义 |
| ------ | ---- |
| `0 0/5 * * * ?` | 每 5 分钟 |
| `0 0 * * * ?` | 每小时整点 |
| `0 0 2 * * ?` | 每天 02:00 |
| `0 30 9 ? * MON-FRI` | 工作日 09:30 |
| `0 0 1 1 * ?` | 每月 1 号 01:00 |

注意两点：

- 「日」和「周」通常一个用 `?`，另一个指定值；
- 表达式长度不超过 200 字符。

不想手写可以点「可视化生成」：

- 秒、分、时、日、月、周逐项配置；
- 支持常用模板（每分钟、每 5 分钟、每天 8 点、工作日 9 点等）；
- 实时校验并预览未来 10 次执行时间。

![Cron 生成器](/images/cron-helper.png)

### 3.2 禁止并发执行

开启后，同一作业上一次执行未结束时，新的触发会等待上一次完成，而不是并发执行。适合执行时间可能超过调度间隔的作业。

### 3.3 前置依赖

多选需要先成功的作业，按「分组 / 作业名」展示。执行规则：

1. 触发时逐个检查依赖作业最近一次执行结果；
2. 全部成功才执行本作业；
3. 有任意一个未执行或失败，本次跳过，并写入「已跳过」日志。

保存时会校验：不能依赖自己、依赖必须存在、不能形成循环依赖。

### 3.4 失败重试

| 字段 | 范围 | 说明 |
| ---- | ---- | ---- |
| 重试次数 | 0–10 | 0 表示不重试 |
| 重试间隔 | 1–3600 秒 | 仅在重试次数大于 0 时可填 |

重试只适合幂等作业。发消息、扣库存、转账这类作业请保持 0，或自行在业务上做幂等。

### 3.5 中断补跑

三态选择：

| 选项 | 含义 |
| ---- | ---- |
| 跟随全局 | 由「系统设置 → 停机与恢复 → 默认允许中断补跑」决定 |
| 开启 | 该作业在进程中断后一定补跑 |
| 关闭 | 该作业一定不补跑，优先级最高 |

补跑是整段重跑，不是断点续传。

## 4. 作业配置（DLL）

### 4.1 作业类名

下拉列表来自当前应用已加载程序集中所有实现 `IJob` 的类，支持搜索，也可以直接输入完整类名（含命名空间）。

作业类必须：

- `public`；
- 不是抽象类；
- 实现 `Quartz.IJob`。

如果下拉里没有你的类，先确认程序集已被加载、类已编译进当前应用。

### 4.2 作业数据

JSON 格式，执行时通过扩展方法读取：

```csharp
using Chet.QuartzNet.Core.Extensions;

var json = context.JobDetail.JobDataMap.GetJobDataJson();
var data = context.JobDetail.JobDataMap.GetJobData<OrderSyncParam>();
```

输入框支持失焦自动格式化与「JSON 格式化」按钮，格式非法会直接校验失败。

## 5. 作业配置（API）

![API 请求头编辑器](/images/job-api-headers.png)

| 字段 | 说明 |
| ---- | ---- |
| API 地址 | 必填，必须是绝对地址且为 http / https |
| 请求方法 | GET / POST / PUT / DELETE / PATCH |
| 超时（秒） | 1–99999，默认 60 |
| 跳过 SSL 验证 | 仅建议在开发/测试环境使用 |
| API 请求头 | Key-Value 编辑器，支持常用请求头下拉与手动添加 |
| API 请求体 | JSON 格式；选择 GET 时界面会提示通常不需要请求体 |

请求头与请求体都会做 JSON 校验，保存前可以先点「JSON 格式化」检查。

## 6. 其他设置

| 字段 | 说明 |
| ---- | ---- |
| 描述 | ≤500 字符，建议写清业务含义与负责人 |
| 是否启用 | 关闭后不参与调度，但配置与日志保留 |

## 7. 保存后如何验证

1. 在列表中找到刚创建的作业，确认「下次执行」时间是否符合预期；
2. 点击「立即执行」手动触发一次（会忽略暂停状态与依赖校验）；
3. 打开日志页，确认出现一条「手动」来源的记录；
4. 失败时打开详情看异常与作业数据。

## 8. 常见错误

| 现象 | 原因 |
| ---- | ---- |
| 保存提示 Cron 无效 | 段数不对、日/周同时指定、使用了不支持的字符 |
| 作业类下拉为空 | 应用内没有实现 `IJob` 的公开类，或程序集未加载 |
| 保存提示作业类无效 | 填写的类名无法解析，或类型未实现 `IJob` |
| API 保存失败 | 地址不是 http/https 绝对地址，或请求头/请求体不是合法 JSON |
| 作业到点没执行 | 作业被禁用、调度器已停止、处于排水状态 |
| 一直没有执行日志 | 检查调度器状态与 Cron，必要时手动执行验证 |
| 依赖配置保存失败 | 自依赖、依赖不存在或循环依赖 |

## 9. 命名与分组建议

- 名称用小写 + 短横线：`order-sync`、`report-daily`；
- 分组按业务域：`ORDER`、`REPORT`、`SYSTEM`；
- 同一链路使用统一前缀，便于搜索和配置依赖；
- 描述写清输入、输出与负责人，出问题时能快速找到人。

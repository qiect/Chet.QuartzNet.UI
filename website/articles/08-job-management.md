# 作业管理介绍

作业页承担两类操作：对单个作业的增删改查，以及对调度器本身的启动、停止与排水。理解「暂停」和「禁用」的区别，是用好这个页面的前提。

![作业管理](/images/job.png)

## 1. 列表与筛选

### 1.1 列信息

| 列 | 说明 |
| -- | ---- |
| 作业名称 / 分组 | 唯一标识 |
| 作业类型 | DLL / API |
| 作业类名 / API | DLL 显示完整类名，API 显示地址 |
| Cron 表达式 | 当前调度规则 |
| 上次执行 / 下次执行 | 来自调度器实时值；禁用时不显示下次执行 |
| 状态 | 正常、已暂停、已完成、错误、阻塞 |
| 中断补跑 | ⚡ 开启、⊘ 关闭、— 跟随全局 |
| 前置依赖 | 已配置的依赖作业 |
| 是否启用 | Switch 开关 |
| 创建时间 | 支持排序 |

### 1.2 筛选与排序

- 按作业名称、分组、类名/API 搜索；
- 按状态与是否启用筛选；
- 服务端分页与排序，默认按创建时间倒序；
- 搜索条件与列设置会持久化，刷新后保留。

## 2. 状态与两个开关

### 2.1 作业状态

| 状态 | 含义 |
| ---- | ---- |
| 正常 | 触发器正常，等待下次执行 |
| 已暂停 | 触发器被暂停，不会执行 |
| 已完成 | 一次性触发已结束 |
| 错误 | 调度或执行出现错误 |
| 阻塞 | 触发被阻塞 |

枚举中还定义了已完成、错误、阻塞三种状态；日常 Cron 作业通常只会看到「正常」与「已暂停」。

### 2.2 启用 / 禁用 与 暂停 / 恢复

这两个动作看起来都能“让作业不跑”，但语义不同：

| 动作 | 影响 | 持久化 | 恢复方式 |
| ---- | ---- | ------ | -------- |
| 禁用 | 从调度器删除作业（并中断执行中的实例） | 是（`IsEnabled=false`） | 打开开关重新启用 |
| 暂停 | 触发器暂停，作业仍在调度器中 | 状态为 Paused | 点击「恢复」 |
| 停止调度器 | 所有作业停止触发 | 运行态 | 启动调度器 |

注意：**批量启用会保留作业原来的暂停状态**。原来处于暂停的作业，启用后仍然是暂停，不会因为一次批量启用就自动运行。

## 3. 单个作业操作

操作列在鼠标悬停时展开，包含：

| 操作 | 行为 |
| ---- | ---- |
| 编辑 | 修改 Cron、重试、并发、依赖、作业配置等 |
| 复制 | 以现有配置创建副本，名称与分组自动加 `_Copy` |
| 立即执行 | 手动触发一次，忽略暂停状态与依赖校验 |
| 停止 / 恢复 | 暂停或恢复该作业的触发器 |
| 删除 | 删除作业及其关联日志；执行中的实例会被中断，不可恢复 |

「立即执行」只表示触发请求已提交，执行结果需要到日志页查看。

## 4. 批量操作

勾选多个作业后，工具栏出现批量操作菜单：

- 批量停止（暂停）；
- 批量恢复；
- 批量启用；
- 批量禁用；
- 批量删除。

未选中作业时按钮禁用，执行前有二次确认，完成后返回成功与失败数量。

## 5. 作业依赖

在编辑对话框的「前置依赖」中配置，执行时按以下规则处理：

1. 依赖作业最近一次执行成功 → 继续；
2. 未执行、失败或已跳过 → 本次跳过；
3. 跳过会写一条「已跳过」日志，消息中说明原因。

例如：

```text
前置依赖未满足，本次执行已跳过：
demo.job-a 最近一次执行状态为 Failed
```

手动「立即执行」不校验依赖，用于依赖异常时补跑。配置保存时会拦截自依赖、不存在的依赖与循环依赖。

## 6. 调度器状态与排水

页面顶部状态条展示当前调度器实例：

- 运行状态（运行中 / 待机 / 排水中 / 已停止）；
- 线程池上限与执行中数量；
- 启动时间；
- 操作按钮：启动调度器、停止调度器、排水、恢复调度。

### 6.1 三种停机方式

| 操作 | 是否接收新触发 | 是否等待执行中任务 |
| ---- | -------------- | ------------------ |
| 停止调度器 | 否 | 否，立即关闭 |
| 排水 | 否 | 是，等待收尾或超时 |
| 恢复调度 | — | 排水未完成时退出排水 |

排水期间：

- 顶部显示「排水 · 等待 N 个任务完成」；
- 启动按钮置灰，手动触发会被拒绝并提示原因；
- 执行中任务归零后自动关闭调度器；
- 超时未完成的任务被标记为「中断」，下次启动按补偿策略处理。

## 7. 常见操作建议

### 7.1 发布前

1. 点击「排水」，等待执行中任务收尾；
2. 确认状态变为已停止后再发布；
3. 启动新版本后检查「运行态」与「待补偿」数量。

### 7.2 临时停掉一批作业

优先使用批量禁用，而不是逐个删除；恢复时批量启用即可。

### 7.3 调整 Cron

直接编辑保存，调度器会按新表达式重新排程；不需要删除重建。

### 7.4 排查“作业没跑”

按顺序检查：

1. 作业是否启用；
2. 状态是否暂停；
3. 调度器是否运行、是否处于排水；
4. Cron 的下次执行时间是否合理；
5. 日志中是否有「已跳过」与依赖原因。

## 8. 页面没有提供的功能

为避免误解，列出几个常见但**不存在**的能力：

- 单个作业的执行统计图表（统计在分析页，按全局维度）；
- 按作业单独配置通知渠道（通知为系统级配置）；
- 作业详情独立页面（配置在编辑对话框，结果在日志页）；
- 简单调度 / 日历调度（仅支持 Cron 表达式）。

# 通知管理介绍

通知页解决两个问题：**怎么发**（配置与策略）和**发得怎么样**（历史与错误）。配置项的完整说明在 [通知功能详解](/articles/03-notification-guide)，这一篇聚焦页面操作与日常管理。

![通知管理](/images/notification.png)

## 1. 页面结构

| 区域 | 内容 |
| ---- | ---- |
| 工具栏 | 通知配置、发送测试通知、清空 |
| 筛选区 | 通知状态、触发来源 |
| 列表 | 标题、来源、状态、发送时间、耗时、创建时间、操作 |
| 详情弹窗 | 完整内容、错误信息、时间与耗时 |

## 2. 通知配置

点击「通知配置」打开对话框，分为四块。

### 2.1 基础配置

| 配置项 | 说明 |
| ------ | ---- |
| 服务启用状态 | 总开关，关闭后不发送任何通知 |
| Token | PushPlus Token，必填 |
| 推送渠道 | 微信公众号、企业微信、Webhook、邮件、短信、语音、浏览器扩展、App |
| 消息模板 | HTML / Markdown / TXT / JSON |

### 2.2 渠道参数

| 配置项 | 说明 |
| ------ | ---- |
| 业务主题（Topic） | 群组编码，不填则发给个人 |
| 渠道配置（Option） | webhook 填 Webhook 编码；cp 填企业微信应用编码；mail 可选自定义邮件渠道 |
| 接收人（To） | 好友令牌或企业微信用户 id，多人用逗号分隔 |

选择不同渠道时，对话框会动态展示对应提示与必填校验。例如选择 webhook 后，`Option` 为空会直接阻止保存。

### 2.3 高级配置

- **回调地址**：接收 PushPlus 的发送结果回调，选填；
- **有效期时间戳**：毫秒时间戳，服务器时间超过该值则不发送。

### 2.4 通知策略

| 策略 | 默认值 |
| ---- | ------ |
| 作业执行成功 | 关闭 |
| 作业执行失败 | 开启 |
| 调度器系统异常 | 开启 |

![通知配置](/images/notification-config.png)

## 3. 消息模板

v2.7.0 起模板改为卡片式选择器，选中后下方实时预览；模板预览改为悬停浮层，标题栏只保留「推送预览」入口。

| 模板 | 适合场景 |
| ---- | -------- |
| HTML | 微信内阅读，带颜色与表格 |
| Markdown | 技术人员阅读，结构清晰 |
| TXT | 短信、语音等纯文本渠道 |
| JSON | 对接下游系统或自动化流程 |

JSON 模板输出示例：

```json
{
  "eventType": "jobExecution",
  "jobName": "order-sync",
  "jobGroup": "DEFAULT",
  "status": "failed",
  "statusText": "失败",
  "executionTime": "2026-11-17 10:00:00"
}
```

## 4. 测试通知

点击「发送测试通知」，系统会按当前配置发送一条示例消息。

- 成功：提示「测试通知发送成功」；
- 失败：提示失败原因。

测试通知只用于验证 Token、渠道与模板，**不会写入通知历史**；也不代表作业事件一定会触发通知，还需要检查策略开关。

## 5. 通知历史

### 5.1 列表字段

| 字段 | 说明 |
| ---- | ---- |
| 通知标题 | 通常包含作业名与状态 |
| 触发来源 | 作业名或「调度器」 |
| 状态 | 待发送 / 发送成功 / 发送失败 |
| 发送时间 | 实际提交时间 |
| 耗时 | 发送耗时（毫秒） |
| 创建时间 | 记录生成时间 |

### 5.2 筛选与查看

- 按状态筛选；
- 按触发来源搜索；
- 点击「详情」查看完整内容与错误信息。

![通知详情](/images/notification-detail.png)

### 5.3 删除与清空

- 单条删除：操作列删除；
- 清空：按当前筛选条件清空，操作不可恢复。

通知历史会持续增长，建议定期清理，或结合数据库备份策略保留一段时间。

## 6. 与作业的关系

这是最容易误解的地方，明确说明：

| 以为可以 | 实际情况 |
| -------- | -------- |
| 给某个作业单独配接收人 | 不支持，通知是系统级配置 |
| 给某个作业单独选模板 | 不支持，模板全局生效 |
| 作业超时时通知 | 不支持，只有成功 / 失败 / 调度器异常 |
| 作业跳过时通知 | 不发送通知，只在日志中记录「已跳过」 |

如果确实需要按作业分流，需要在宿主应用中自行实现通知逻辑，或通过多个实例 + 不同配置隔离。

## 7. 常见问题

| 现象 | 排查 |
| ---- | ---- |
| 测试通知失败 | Token 是否有效、网络是否可达、渠道必填 `Option` 是否填写 |
| 作业失败但没通知 | 总开关、失败策略、作业是否真的执行（看日志） |
| 通知状态一直「待发送」 | 发送流程异常中断，查看错误信息与服务日志 |
| 群组收不到消息 | `Topic` 是否正确；`Topic` 与 `To` 同时填写时以 `Topic` 为准 |
| 重复通知 | 多实例同时调度同一作业，或作业被重复触发 |
| 通知内容乱码 | 模板与渠道不匹配，改用 TXT 或 Markdown 验证 |

## 8. 使用建议

1. 至少开启「作业执行失败」与「调度器系统异常」；
2. 成功通知只在关键链路开启，避免噪声；
3. 微信渠道优先使用 HTML 或 Markdown；
4. 每次修改配置后发一条测试通知；
5. 定期查看失败记录，Token 过期或渠道变更会直接体现为发送失败。
